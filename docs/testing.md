# FieldOps testing

## Test layers

### PHPUnit

Use feature tests for routes, middleware, Inertia responses, authorization, validation, database behavior, notifications, queues, and security-sensitive workflows. Use unit tests for isolated domain calculations and transformations. Prefer factories and `RefreshDatabase` for database-backed tests.

### Vitest and Testing Library

Use behavior-oriented tests for React components, hooks, forms, navigation, loading/error/empty states, and theme-aware rendering. Query by accessible role, label, and text. Do not make snapshots the sole proof of behavior.

Run the focused suite in watch mode during development, or collect a V8 coverage report before delivery:

```powershell
npm run test:unit
npm run test:unit:coverage
```

The same commands can be run in Docker with `docker compose exec node` when using the optional containerized runtime.

### Playwright

Use browser tests for critical journeys and cross-cutting UI contracts: authentication, dashboard access, settings, responsive layout, keyboard navigation, and light/dark presentation. Run at mobile, tablet, and desktop viewport profiles. Accessibility smoke checks should fail on serious violations.

For the native Laragon runtime, run browser checks against the local virtual host and the production bundle. Playwright changes application data, so point it at a dedicated test database. The default account credentials work only on a clean database seeded with the default accounts; repeat seeding preserves existing passwords. Set the `E2E_*` variables to accounts in that test database when their credentials differ. Playwright checks these accounts once before starting the browser matrix and stops immediately if credentials are invalid or rate-limited. The `public/hot` file is generated by the normal Vite development server, so it is removed for this deterministic browser run:

```powershell
Remove-Item -Force public\hot -ErrorAction SilentlyContinue
npm run build
$env:E2E_BASE_URL = 'http://fieldops.test'
$env:E2E_USER_EMAIL = 'user@example.com'
$env:E2E_USER_PASSWORD = 'password'
$env:E2E_ADMIN_EMAIL = 'admin@example.com'
$env:E2E_ADMIN_PASSWORD = 'password'
$env:E2E_OWNER_EMAIL = 'superadmin@example.com'
$env:E2E_OWNER_PASSWORD = 'password'
npm run test:e2e
```

For Docker, use `E2E_BASE_URL=http://fieldops.test` inside the node container after building there.

## Feature test matrix

Each feature change must cover:

- the successful user journey;
- unauthenticated and unauthorized access where applicable;
- invalid, missing, duplicate, or boundary input;
- persistence and important side effects;
- loading, empty, error, and disabled UI states;
- light/dark and responsive behavior for user-facing UI.

## Verification order

Use fast checks first, then integration and browser checks:

```text
format -> lint -> type/static analysis -> unit tests -> build -> browser tests
```

CI is the final gate. Local verification should use the native Laragon workflow when available; Docker remains a supported alternative for reproducing the containerized runtime.
