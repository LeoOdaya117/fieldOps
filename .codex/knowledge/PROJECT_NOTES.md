# Verified Project Notes

Use this file for durable conventions confirmed from source or canonical project guidance. `$project-init` and `$feature-build` should preserve existing notes and amend only facts that have become stale.

- `AGENTS.md` is the canonical engineering guide for this repository.
- Laravel owns routing, authentication, authorization, validation, persistence, and Inertia page data; React owns presentation and local interaction state.
- Keep controllers thin; use Form Requests for input validation and request authorization, Policies for resource authorization, and Actions for reusable or multi-step operations.
- Frontend code uses strict TypeScript, Inertia state, Wayfinder-generated routes, shared UI primitives, semantic theme tokens, and responsive light/dark behavior.
- Page-level loading uses route-family skeletons from `resources/js/features/page-loading/` for delayed, non-prefetch, non-async GET visits; an empty-root Blade fallback covers the initial client mount. Background Inertia reloads retain mounted content; local operation loading remains owned by each action/widget.
- The repository's test guidance requires success, authorization, validation/failure, side-effect, and relevant UI theme/responsive coverage.
- The documented backend request flow is route -> middleware -> Form Request -> controller -> action/model -> Inertia response; policies or other authorization checks guard resource access (`docs/architecture.md`).
- `bootstrap/app.php` registers `routes/web.php` and `routes/console.php`, the `/up` health path, and project web middleware; `routes/web.php` includes authenticated access-management and system-data groups while `routes/settings.php` defines profile and settings flows.
- `resources/js/app.tsx` bootstraps Inertia and selects shared layouts; route entry pages live in `resources/js/pages/`, with reusable feature behavior under `resources/js/features/`.
- Frontend tests use Vitest with jsdom and `tests/Frontend/`; browser tests use Playwright with mobile, tablet, and desktop projects. PHPUnit covers Laravel feature and unit tests.
- `composer ci:check` coordinates frontend lint, format, type, unit checks and build with Laravel checks; CI additionally runs dependency audits (`.github/workflows/tests.yml`).
- Models using the shared `record_status` trait expose resource-scoped `view_deleted` and `update_deleted` permissions. Controllers pass both capabilities and a resource-specific status URL to the shared status control, gate inactive filters and details on `view_deleted`, and direct transitions through `ChangeRecordStatus`.
- RBAC seeds three protected built-in roles (`user`, `admin`, `super_admin`); only Super Admin is elevated. Admin and Super Admin receive record-status permissions by default, while User does not (`config/rbac.php`, `database/seeders/RbacSeeder.php`).
- User session invalidation increments a per-user `session_version` and rotates the remember token. Login snapshots that version in the session, and `EnsureActiveUser` rejects stale snapshots so file-backed sessions cannot regain access after reactivation (`app/Actions/Security/InvalidateUserSessions.php`, `app/Listeners/SnapshotUserSessionVersion.php`, `app/Http/Middleware/EnsureActiveUser.php`).
- Uploaded files use `MediaAsset` as the canonical record, with immutable opaque tokens for browser-facing references and private Laravel Storage keys generated under `modules/{module}/{year}/{month}/`. The Files workspace and personal gallery have separate list scopes; private content/download routes enforce module and owner permissions (`app/Models/MediaAsset.php`, `app/Policies/MediaAssetPolicy.php`, `routes/web.php`, `config/media-assets.php`).
- `files:backfill-avatars` copies legacy public avatars into private managed assets without deleting sources. The `User::avatar` accessor retains a public-path fallback until a deployment verifies and finishes this migration (`app/Console/Commands/BackfillAvatarFiles.php`, `app/Models/User.php`).
- Table previews for CSV/XLS/XLSX use bounded input and output. Legacy XLS uses PhpSpreadsheet 5.10.0 with a data-only first-sheet/first-rows filter and a per-user preview rate limit; the PHP ZIP extension is required by that Composer package (`app/Actions/Media/BuildFilePreview.php`, `app/Actions/Media/FirstRowsReadFilter.php`, `app/Providers/AppServiceProvider.php`, `composer.json`).
- Listing pages and global exports share resource query builders in `app/Actions/DataTables/BuildListingQuery.php`; export-safe columns and dataset permissions are defined by `app/Actions/Exports/ExportDatasetRegistry.php`. Generated reports use expiring private artifacts and recheck the owner’s current permission and file scope at access (`app/Actions/Exports/ExportArtifactAccess.php`, `app/Actions/Exports/ExportReportWriter.php`).
- Shared data table action controls shrink and wrap within the available toolbar width, keeping filters and export controls reachable at tablet sizes (`resources/js/components/ui/data-table.tsx`).
- New Print and PDF reports use the same Dompdf layout on A4 portrait pages. Wide reports use compact table typography to fit portrait width. Print keeps its separate permission and guarded route but stores a PDF served inline; legacy HTML Print artifacts remain accessible under the same checks until expiry (`app/Actions/Exports/ExportReportWriter.php`, `app/Http/Controllers/Exports/ExportController.php`).
- Print/PDF report requests can include ordered visible table-column keys. `StoreExportRequest` validates them against `ExportDatasetRegistry::reportColumnMap`, `ExportController` snapshots them in artifact filters, and `GenerateExportArtifact` resolves them when writing the PDF. CSV/XLSX use their legacy fixed columns; Print/PDF callers without a selection use the fixed data columns plus `#` on numbered datasets (`app/Http/Requests/Exports/StoreExportRequest.php`, `app/Http/Controllers/Exports/ExportController.php`, `app/Actions/Exports/GenerateExportArtifact.php`).
- Print/PDF requests also snapshot the viewer's validated timezone and locale plus the source application timezone, allowing queued reports to format dates like the table and restore worker timezone afterward. Numbered datasets receive a server-generated `#` column in report order, including when a caller omits a column selection; CSV/XLSX keep their existing data layout. PHP Intl is a required runtime extension (`app/Actions/Exports/ExportDatasetRegistry.php`, `app/Actions/Exports/GenerateExportArtifact.php`, `composer.json`).

Add new notes only with a source or instruction path that supports them. Do not store credentials, `.env` values, or sensitive data here. Refreshed 2026-10-01 with the global export query, permission, and artifact paths.

- Database backup packages, operation history, writer locks and authentication epoch use durable private local filesystem state through `app/Actions/Backups/BackupStore.php`. `backups:work` processes operations independently of the restored database and application queue. Native MySQL/MariaDB engine operations and signed package contracts live in the same feature action directory (`config/backups.php`, `docs/database-backups.md`).
- Restore maintenance precedes database-dependent HTTP middleware and holds an exclusive writer lease after existing HTTP/Artisan writers stop. Successful recovery resets runtime tables and rotates remember tokens plus the external authentication epoch; failed destructive recovery retains maintenance (`bootstrap/app.php`, `BackupWriterLease`, `ConsoleWriterLease`, `ExecuteBackupOperation`, `EnsureActiveUser`, `SnapshotUserSessionVersion`).
- Backup routes under System Settings explicitly require active, verified Super Admin access, with recent password confirmation and mutation/download throttling. Real-engine verification is opt-in on disposable schemas and has a MySQL 8.4/MariaDB 11.4 workflow (`routes/settings.php`, `tests/Feature/Backups/DatabaseBackupIntegrationTest.php`, `.github/workflows/database-backups.yml`).
- Selected database packages use signed version 2 scope, requested/included table, creator and audit-note metadata. The resolved scope expands bidirectional foreign keys and registered FieldOps logical links; a restore replaces the complete recorded scope after taking a full safety package. CLI `--recovery` accepts only full database packages. Backup inventory and audit pages are separately searchable and paginated over durable filesystem history (`BackupPackage`, `BackupTableScope`, `BackupStore`, `ExecuteBackupOperation`, `resources/js/features/backups/`).
