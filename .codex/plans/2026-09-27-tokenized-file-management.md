# Implement tokenized file management in FieldOps

Status: In progress (updated 2026-09-29; production avatar cutover outstanding)

## Goal and acceptance criteria

Extend the existing `MediaAsset` subsystem into the single record for uploaded files. Add a central Files list and detail page, private token-based preview and download, and a reusable dropzone. Preserve the personal image gallery, profile photos, and platform branding while moving their file references to tokens.

Acceptance criteria: all uploaded-file interfaces, including preview and download, identify files by opaque tokens rather than storage paths or numeric IDs; private requests still require authentication and owning-module authorization; administrators can manage files across uploaders in modules they are authorized to manage, while the personal gallery stays owner-scoped. Files list and detail show suitable thumbnails or type icons, readable size, nullable image dimensions, module, tag, status and dates. Images and PDFs preview inline, CSV/XLS/XLSX have bounded escaped table previews, and unsupported types remain downloadable. A configurable accessible dropzone and shared upload hook record each successful file once. Storage is private, keyed by module/year/month, with S3-compatible disk selection. Existing media, avatars and platform branding continue to work with token references; inactive bytes are retained and protected by view_deleted permissions.

4. Add `/files/{token}` detail, content, thumbnail, preview-data, download, update, delete, and record-status routes. Replace numeric file URLs and upload-selection payloads with tokens, retaining numeric internal foreign keys if needed. Remove numeric delivery routes after migration. 5. Add searchable paginated Files list and detail/preview, thumbnails/type icons, metadata, safe preview handlers and audited token downloads.

## Assumptions

Tokens identify files but do not themselves authorize private access. Built-in static assets are out of scope. Admins may access cross-uploader files only within managed modules; personal picker stays uploader-scoped. Unsupported previews remain downloadable. MIME acceptance is explicitly configured and validated server-side. Inactive files retain bytes; only users with module `view_deleted` permission may inspect them.
